# AGENTS.md: PDFPaper

## Project goal
PDFPaper is a native Android PDF app with its own PDF engine (no third-party
PDF library for core parsing/rendering). Long-term goal: similar feature set to
PdfCraft (view, organize, merge/split, annotate, forms, encryption), designed
for touch. Do not copy PdfCraft/ArtCraft code, logos or branding.

## Tech decisions (change only when the owner approves)
- Language: Kotlin (engine in a pure-Kotlin module with no Android imports)
- UI: Jetpack Compose + Material 3, MVVM
- Build: Gradle Kotlin DSL; minSdk 26, targetSdk/compileSdk 34
- Modules: :app (UI), :engine (PDF engine, pure Kotlin/JVM), :convert (PDF↔office converters, pure Kotlin/JVM, depends on :engine only), :signatures (PDF signature validation, pure Kotlin/JVM, depends on :engine only; JDK JCA plus its own DER/CMS reader), :engine-tests data in /testdata
- Reference: ISO 32000-1 (PDF 1.7). Cite the section number in code comments.

- Last session: 2026-10-19 — T25 (engine) done. `:engine` can now add an invisible OCR text layer to scanned pages (ISO 32000-1 §9.3.6, §9.7.5, §9.10.3). The OCR engine itself stays in the app: `ocr/OcrProvider` is a `fun interface` (`recognize(image, language): List<OcrWord>`) over `OcrImage` (32-bit RGBA row-major, row 0 at the top; when the engine cannot decode the codec the still-encoded DCT/JPX bytes + format are handed over, so the host decoder is the only platform piece) and `OcrWord(text, bounds, confidence)` with pixel bounds (origin top-left, y down). `PdfOcr.makeSearchable(document, provider, language = "eng", pages = null)` returns `Result<SearchableResult(bytes, List<OcrPageReport>)>`; with `pages` null every page without extractable text is processed, otherwise exactly the listed zero-based indices are processed even if they already have text. Per page the largest image drawn in the page content or a nested form XObject is the OCR input (inline images are not collected), and each word becomes an `AddOcrTextEdit` appended as `q / Tr 3 / BT / Tf / Tz / Tm / Tj / ET / Q`, so the original content streams and image XObjects are copied untouched. The text matrix follows the image's own axes with unit scale, the font size is the word's height in page units and `Tz` stretches the run (one em per character from `/DW 1000`) to the word box width exactly, so extraction/search/selection boxes equal the provider's boxes even when the image is scaled or rotated. Words are drawn with one shared glyph-less Type0 font per save (`OcrTextFont`: `/Identity-H`, two-byte CIDs equal to the Unicode code point, ToUnicode `bfchar` blocks of ≤100, `/DW 1000`, FontDescriptor without FontFile2 — render mode 3 paints nothing, so no font program is needed and Android needs none); the font is created lazily, only when at least one word is added, and shared by every page. Statuses `ADDED` / `SKIPPED_HAS_TEXT` / `NO_IMAGE` / `PROVIDER_FAILED` / `NO_WORDS`; provider exceptions are caught per page, blank/inverted/non-BMP words are dropped, and every report carries the image size plus the mean/min confidence of the words actually added. CLI: `./cli ocr <file.pdf> [--lang eng+hin] [--out out.pdf] [--pages 1,3-5] [--text <words...>]` uses a deterministic stub provider that lays `--text` out on a grid (default "PDFPaper sample OCR text"); `--out` defaults to `out.pdf`, exit 1 for IO errors, 0 otherwise. 10 new `PdfOcrTest` tests (423 engine tests total, 0 failures) cover exact word boxes and font size in page space, `renderMode == 3`, search hits for a word and a phrase after a save/reopen, Hindi text through ToUnicode, skipping pages with text, forced `pages`, provider failure, no image, blank/inverted words, no font when nothing is added, one shared font across pages, and a scan inside a form XObject whose CTM composes the page `cm` with the form `/Matrix`; `./gradlew build` is green, and CLI acceptance was re-read with pypdf and PyMuPDF (text extractable and searchable, `search_for("world")` returns the word's rectangle, and a 72 dpi render of the OCR'd file is byte-identical to the original, i.e. the layer is truly invisible).
- Last session: 2026-10-19 — T24 (signatures) done. New pure-JVM `:signatures` module (depends on `:engine` only; **no BouncyCastle**): `PdfSignatures.verify(file|bytes|source, TrustStore)` validates every AcroForm signature field and returns `SignatureVerification` with one `SignatureReport` per field. It reads `/ByteRange`, `/Contents`, `/SubFilter` (`adbe.pkcs7.detached`, `ETSI.CAdES.detached`, legacy `adbe.pkcs7.sha1`), `/Filter`, `/Name`, `/Reason`, `/Location` and `/M`, and parses the CMS with a small definite-length DER reader (`der/Der.kt`, `cms/Cms.kt`): SignedData, certificates, SignerInfo, CRLs, signed `messageDigest`/`contentType`/`signingTime`, unsigned revocation info and Adobe's `adbe-revocationInfoArchival`. Checks: (1) recompute the digest over the two signed ranges and compare it with the signed `messageDigest` (or the legacy embedded SHA-1); (2) verify the CMS signature with the signer certificate — signed attributes are re-tagged from `[0]` to `SET OF` exactly as CMS requires, and a no-attributes signature is verified over the content itself; (3) build a PKIX chain against the caller's `TrustStore` (`trustAnchors()`/`intermediates()`, implemented on Android by the platform store and on the JVM by `TrustStores.system()`/PEM/keystore loaders), checking every certificate's current validity dates, with the anchor reported; (4) treat non-whitespace bytes after the signed ranges as post-signing incremental updates and report their offset/length plus each `%%EOF` marker. Revocation only ever uses data embedded in the CMS: a matching, in-date, signature-verified CRL gives `GOOD` or `REVOKED`; embedded OCSP is reported as not checked; otherwise `NOT_CHECKED` — the verifier never touches the network. States are `INTACT_AND_TRUSTED`, `INTACT_SIGNER_UNKNOWN`, `MODIFIED_AFTER_SIGNING`, `INVALID`, `UNSUPPORTED`, aggregated by severity `INVALID > MODIFIED_AFTER_SIGNING > UNSUPPORTED > INTACT_SIGNER_UNKNOWN > INTACT_AND_TRUSTED`; encrypted PDFs are `UNSUPPORTED` (the engine decrypts strings, but `/Contents` must stay raw). CLI: `./cli signatures verify <file.pdf> [--truststore <pem|jks|pkcs12>] [--password <pw>]`, defaulting to the JVM trust store. The 12 committed PDF fixtures plus 6 PEM certificates are generated by `signatures/tools/make_fixtures.py` (dev-only Python + OpenSSL; keys stay in `build/`), and 17 tests cover trusted/untrusted/expired/revoked/no-attributes/legacy-SHA-1, tampered, modified-after-signing, unsigned, unsupported, malformed ByteRange and 27 truncation/bit-flip no-crash samples. `./gradlew build` green; fixtures were independently accepted by pypdf, PyMuPDF (`SigFlags=3`, one signature widget) and `openssl cms -verify` (including the expected rejection of the tampered file). No signing is implemented.

All three entrances (picker, Recent, VIEW intent) share one route and one view model so they cannot drift, and a PDF picked this way goes straight to the viewer while an office file is converted on `Dispatchers.Default`. Recent entries store the kind (`pdf`/`docx`/`pptx`) beside the URI in the same Base64 TSV records, so old two-field records decode as PDFs and the row can say what the file was; re-opening re-reads the bytes rather than trusting that label. `PackageCheck.parse` now wraps `setExpandEntityReferences`/`setFeature(disallow-doctype-decl)` in `runCatching`: Android's `DocumentBuilderFactory` throws for features it does not know, and a *valid* part must not turn into a parse error — this is the first time `:convert` runs on Android, and the device tests (3 conversions, 3 banner, 2 end-to-end flow) are what prove the reader, the layout and the hand-written PDF writer work there. The three sample files are generated by a dev-only script (`app/tools/make_office_samples.py`, python-docx/python-pptx) and committed in both test trees because unit tests read test resources and device tests read assets from the test APK.

- 2026-10-19 (T21 engine): no new dependencies. The standard-14 AFM tables moved from `convert/.../pdf/StandardWidths.kt` into the engine (`engine/.../edit/StandardWidths.kt`, `internal`, with `Standard14` as the typed façade) so PDF creation and the DOCX/PPTX→PDF layout share one generated source of truth instead of a drifting copy; the dev-only reportlab generator now writes the engine path. The builder's coordinates put the origin at the top-left with y growing downward (text is positioned by its baseline), because that is what a caller has on hand from a UI or a raster; the writer flips y once at serialisation. Content streams are uncompressed ASCII and every used font is written with `/WinAnsiEncoding` + explicit `/Widths`, so viewers advance the glyphs identically; image XObjects reuse the T17 `edit/ImageXObjects` (JPEG verbatim under `/DCTDecode`, PNG re-deflated with an `/SMask` when transparent). `ImageFit.FIT` scales to contain, `FILL` scales to cover and wraps the draw in a `re W n` clip to the margin box (an image cannot be cropped by `cm` alone), `ORIGINAL` treats 1 px as 1 pt; margins are points on every side and every mode centres the result. `PdfFromText` collapses whitespace runs to one space, breaks a word wider than the line at a character, keeps blank lines as line boxes, drops a single trailing newline and a leading UTF-8 BOM, and paginates by whole line boxes (empty text still produces one blank page). The CLI expands `*`/`?` itself because cmd.exe and PowerShell do not expand wildcards for a batch file, `--out` defaults to `out.pdf`, and `--size` accepts `A4`/`Letter`/`WIDTHxHEIGHT` in points. Acceptance was checked with two other viewers, not with the engine: pypdf and PyMuPDF both read every CLI output (page counts, media boxes, `/Info` title, the embedded JPEGs, and the full 120-line text with no missing line), and PyMuPDF rendered the pages to bitmaps for the layout checks.

- 2026-10-19 (T22 engine): no new dependencies (JDK `java.time` only). Comment state follows ISO 32000-1 §12.5.6.3 literally: the state is *not* an entry on the comment but a separate hidden `Text` annotation that replies to it with `/IRT` (and, when the same author changes their mind, chains to their previous state annotation), carrying `/State` + `/StateModel /Review` and `/F 30` (Hidden|Print|NoZoom|NoRotate) — exactly what Acrobat DC writes, so a comment written here shows its "Resolved" state in Acrobat and LibreOffice rather than only in our own reader. "Resolved" *is* the Review/Completed state; the reader implements LibreOffice's rule, that a comment is resolved when any reviewer's latest state is Completed, while `PdfComment.status` still shows the newest state overall, and it follows state-to-state `/IRT` chains because real files contain both chained and direct forms. Dates are parsed by a small `PdfDate` helper (§7.9.4: `D:` optional, every field after the year optional, `Z`/`+HH'mm'` offsets, a fractional second) that returns null instead of throwing on malformed input; the engine writes UTC. Ids shown by `comments list` are object numbers *of that file*: every save renumbers objects, so `PdfComments.edit` validates reply/status targets against a fresh comment index of the document it is editing and never trusts an id across saves. Deletion is a closure computed in the engine (popup, replies, state changes, transitively) and applied by telling the assembler's copier those numbers map to "dropped" *before* any page is copied, so a saved file can never keep a dangling `/Popup`/`/IRT`/`/Parent` reference; unknown ids fail the whole edit with a message instead of silently doing nothing. The copier's old "skip `/Parent` on every annotation" rule was narrowed to widgets: it silently detached pre-existing popups from their comments on re-save, and a widget is the only case where `/Parent` would drag the AcroForm in (a link annotation's `/Dest` array entries still come along in copies — the T10 link-keying rule is unchanged). Replies are `Text` annotations with a note-icon appearance stream, `/F 28` (Print|NoZoom|NoRotate) and the target's colour, matching Acrobat's reply look; new popup windows are 216×108 with `/Parent`, `/Open` and no appearance stream (§12.5.6.14), are placed beside the target inside the crop box, and are excluded from listings. `comments delete` was deliberately left out of the CLI — the task lists list/add/reply/set-status only — so deletion is exercised through the engine API and tests. `--text` in the CLI takes the words up to the next `--option`, so a sentence does not need quoting from cmd.exe (where the batch wrapper's nested quotes are unreliable). Acceptance used pypdf (dictionary-level: `/Popup`↔`/Parent`, `/IRT`, `/RT`, `/State`/`/StateModel`, flags, quads) and PyMuPDF/MuPDF (annot + popup listing and a rendered bitmap) as the two other viewers, the same approach as T21.

- 2026-10-19 (T23 engine): no new dependencies (JDK Base64/time only). The library is data, not UI: `StampDesign` is what both the CLI and a future picker list, and `StampCatalogue` merges the built-ins with the user's customs (a custom id overrides a built-in id, compared case-insensitively) so there is one lookup path; all artwork is drawn by `StampPainter` from an own palette (banners, a double-ruled certificate frame with letter tracking, a filled sign-here arrow, image art) — nothing is copied from any product. Rotation is *baked* into the appearance as a `cm` (90: `0 1 -1 0 h 0`; 180: `-1 0 0 -1 w h`; 270: `0 -1 1 0 0 w`) with the `/BBox` set to the *visual* box, rather than using `/Rotate` on the form: `/Rotate` is a page-rotation concept, a baked matrix renders identically in every viewer and matches what the engine's own display list already does with form XObjects; an angle that is not a quarter turn snaps to the nearest, and the placed box swaps width/height on 90/270 (x/y is always the bottom-left of the *placed* box). Opacity is written twice on purpose: the appearance sets `/GS0 gs` (`/ca`/`/CA`) so the appearance alone is authoritative, and the annotation mirrors `/CA` as the fallback that lazy viewers look at without running the appearance; PyMuPDF's 150 dpi render of a 0.5 image stamp measured exactly one 50 % blend, so no tested viewer double-applies them (that is why `/CA` stays; if a viewer ever does, `/CA` is the line to drop). Dynamic stamps put the same sentence in `/Contents` ("Label - By Alice, 2026-10-19 12:30") so a reader that only lists comments still shows who and when; `/T` is the author, `/Subj` the group label, and the date is UTC `yyyy-MM-dd HH:mm` because the engine has no locale and a file must read the same everywhere. Custom stamps are self-contained JSON: a text stamp keeps its text and three colours, an image stamp keeps its original JPEG/PNG bytes (base64) plus format and pixel size, so a shared list needs no sidecar; unknown keys are ignored (forward compatibility), duplicate ids rejected, colours clamped to 0..1 and image bytes validated by magic bytes only — the JSON layer never needs a decoder, which is what lets it run on Android where ImageIO does not exist. Decoding happens at *placement* time instead (`StampSpec.image` takes an `ImageData` the caller decoded; the CLI uses `EditImages.decode`, Android callers must pass `RasterDecoder`). The writer reuses `PdfComments.edit`, so stamps inherit the T22 validation/save path and appear in `comments()` as `STAMP`; a bad spec (non-positive size, image art without pixels, out-of-range page) writes nothing, exactly like T22's out-of-range dispatch, so a batch never writes a half-broken annotation. `/Name` is written only when the design has a standard name (Approved, Final, Confidential, Draft, Expired) because the spec's table is a closed vocabulary — inventing names for the other designs would be worse than leaving them out.

- 2026-10-19 (T24 signatures): no new dependencies and no BouncyCastle — the owner asked first, and the JDK's JCA (`MessageDigest`, `Signature`, `CertificateFactory`, PKIX `CertPathBuilder`) plus a small definite-length DER/CMS reader cover every required check, so the license/size question did not arise. The public seam is `TrustStore` (anchors + optional intermediates) because Android and the JVM have different system stores; the CLI defaults to the JVM cacerts, tests pass PEM roots, and an empty store produces `INTACT_SIGNER_UNKNOWN` with chain `NOT_CHECKED` rather than a failure. `/ByteRange` must start at 0, be ordered, non-overlapping and in bounds; exactly one gap must be the `/Contents` hex string (angle brackets optional, trailing zero padding tolerated), a non-whitespace gap in the middle is invalid, and non-whitespace bytes after the last range are an incremental update (offset/length plus every `%%EOF`). The CMS digest is compared with the signed `messageDigest` attribute; the signature is verified over the original signed-attribute bytes with only the outer tag changed from `[0]` to `SET OF` (a required CMS re-tag), or over the content when no attributes exist; `adbe.pkcs7.sha1` checks the embedded SHA-1 and then verifies the CMS. Chains use PKIX with revocation disabled and every certificate checked at the current time, so an expired signer or anchor is untrusted rather than silently accepted. Revocation consults only embedded CRLs (issuer certificate must be present, CRL signature/dates verified) and reports `GOOD`/`REVOKED`; embedded OCSP and the absence of data are `NOT_CHECKED`/`UNKNOWN`, never a network fetch. Encrypted PDFs are `UNSUPPORTED` because the engine decrypts strings but signature `/Contents` must stay raw; multi-signer CMS and RSA-PSS are also `UNSUPPORTED`. The fixtures are generated once by `signatures/tools/make_fixtures.py` with OpenSSL (dev-only, like the T13/T19 generators; private keys stay in `build/`), and the CRL fixtures are produced by inserting a real OpenSSL `ca` CertificateList into the SignedData `crls [1]` field, because `openssl cms -sign` cannot embed one. No signing is implemented. App-side signature UI and device acceptance are deferred (T24 is engine+CLI only).

- 2026-10-19 (T25 engine): no new dependencies, and the engine contains no OCR library at all — `OcrProvider` is the seam and the app supplies the implementation, exactly like `ExternalImageDecoder`; `OcrImage` therefore carries either RGBA bytes or the still-encoded DCT/JPX stream, so the platform decoder (`:app` already has one for rendering) is the only host piece. Bounds are image pixels with a top-left origin because that is what OCR engines return; `PdfOcr` tracks the standard image-space CTM through the page content and nested form XObjects (the same `ImagePlacements` walker the image editor uses), so a scan that is scaled, flipped or rotated on the page needs no special case and the result does not depend on the display list's internal image-space convention. The word run uses a unit-scale text matrix along the image's axes and a font size equal to the word height *in page units* (not pixels), with `Tz` fitting the advance to the box width: that keeps `PdfTextRun.fontSize` meaningful for T11's same-line and inserted-space thresholds, while the advance still matches the provider's box exactly. The text is appended after the original content (`q`/`Q`, `3 Tr`, one `BT…ET` per word) rather than rewriting the page, so the scan and every original operator survive byte for byte. One glyph-less Type0 font per save (`/Identity-H`, CID = Unicode code point, `/DW 1000`, ToUnicode with ≤100-entry `bfchar` blocks) avoids per-page encoding tables and needs no embedded program because mode 3 never paints; the font is lazy, so a save with no OCR output is unchanged. A page is "already text" when extraction finds any non-blank run, which also makes a second OCR run idempotent; `pages` is the explicit override for partial re-OCR. Provider exceptions are caught per page and reported, never aborting the document, and blank/inverted/astral words are dropped.

- 2026-10-20 (T26 engine): no new dependencies. A visual signature is an ordinary annotation, never a `/Sig` field: drawn strokes are `/Ink` (with a real `/InkList` and per-segment widths from sampled pressure), typed names and pictures are `/Stamp`, and each annotation carries a self-contained `/AP /N` form so no viewer has to guess or run app code. `/PdfPaperVisualSignature << /VisualOnly true /Source ... >>`, `/Subj`, `/Contents` and `VisualSignatureResult.visualOnly` make the non-cryptographic nature explicit at both the PDF and API level. The `/NM` marker is the stable lookup key across saves (object numbers are renumbered), and `list`/`find` only accept annotations carrying the marker with `VisualOnly true`. Editing reuses the assembler: `AnnotationPlacement` updates `/Rect` and wraps a copy of `/AP /N` in a quarter-turn `cm` with a swapped `/BBox` (the same baked-matrix choice as T23), and transforms `/InkList`; no annotation-transform API was added to `PdfPageOps`. Flattening adds `PlaceFormEdit` (paint an existing form into page resources/content with its `/BBox` scaled to the rect) and drops the source annotation object number, so the annotation's appearance and the page content cannot drift or survive twice. Typed fonts are standard-14 WinAnsi only; images are decoded by `EditImages` and transparent white is a placement-time preprocessing step (fixed RGB ≥ 240 cutoff), so the appearance always stores real alpha rather than relying on a viewer's white-key trick. The CLI reuses the standalone `main`+`JavaExec` pattern (`:engine:signvisual`), and the app's existing pending-annotation preview gained an `else -> Unit` branch because `AnnotationSpec` is sealed and `VisualSignatureSpec` is internal; app UI is deferred.

## Release build (T14)
The release variant is minified (`isMinifyEnabled`) and resource-shrunk
(`isShrinkResources`); `app/proguard-rules.pro` keeps `SourceFile` and

   `keytool -genkeypair -v -keystore pdfpaper-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias pdfpaper`
2. Create `/keystore.properties` at the repo root (git-ignored):
   ```
   storeFile=../pdfpaper-release.jks      # relative to :app, or an absolute path

   keyAlias=pdfpaper
   keyPassword=…
   ```

   `app/build/outputs/apk/release/app-release.apk` (plus `app/build/outputs/mapping/release/mapping.txt`

   Without `keystore.properties` the release APK is signed with the debug key:
   installable and verifiable, but not for distribution.

## Crash reporting plan (T14)
No third-party SDK, so the dependency-free build and the absence of a network
permission are preserved.

1. Install one process-wide `Thread.setDefaultUncaughtExceptionHandler` from a
   small `Application.onCreate` (first thing, wrapping the previous handler so
   the platform still shows its dialog). Record ISO timestamp, app
   `versionCode`/`versionName`, Android release/SDK, manufacturer/model,
   available heap, thread name, the full stack trace, and — when a document was
   open — the last file name/size (never its contents).
2. Persist one file per crash under app-private `files/crash/`, newest N kept
   and total bytes capped; swallow the handler's own I/O errors so it cannot
   crash a second time.
3. On next start the Home screen shows a "N recent problem reports" banner;
   sharing is explicit through the system share sheet. Nothing is uploaded and
   no network permission is added.
4. Keep a `CrashSink` interface so a hosted backend can be plugged in later,
   opt-in per build, without changing the capture path.
