# AGENTS.md: PDFPaper

## Project goal
PDFPaper is a native Android PDF app with its own PDF engine (no third-party
PDF library for core parsing/rendering). Long-term goal: similar feature set to
PdfCraft (view, organize, merge/split, annotate, forms, encryption), designed
for touch. Do not copy PdfCraft/ArtCraft code, logos or branding.

## Tech decisions (change only when the owner approves)
- Language: Kotlin (engine in a pure-Kotlin module with no Android imports)
- UI: Jetpack Compose + Material 3, MVVM
- Build: Gradle Kotlin DSL; minSdk 26, targetSdk/compileSdk 34
- Modules: :app (UI), :engine (PDF engine, pure Kotlin/JVM), :convert (PDF↔office converters, pure Kotlin/JVM, depends on :engine only), :engine-tests data in /testdata
- Reference: ISO 32000-1 (PDF 1.7). Cite the section number in code comments.

## Working rules
1. One task per session. Do exactly what the task says, nothing extra.
2. Write tests before or together with the code. Never delete or weaken a test
   to make it pass. If a test is wrong, explain why and ask first.
3. The build must be green (`./gradlew build` and `./gradlew :engine:test`)
   before you say a task is done. Paste the real command output.
4. Never invent file paths, APIs or results. If unsure, read the code or say so.
5. Never crash on bad input: the engine returns errors/results, it does not throw
   uncaught exceptions on malformed PDFs.
6. Keep files small and focused. Prefer clear names over comments.
7. Do not add dependencies without asking. State license and reason.
8. Never run destructive commands (delete, force push, reset --hard) without asking.
9. Stop and report when blocked. Do not guess your way around a blocker.

## Commands
- Build: ./gradlew build
- Engine tests: ./gradlew :engine:test
- Convert tests: ./gradlew :convert:test
- App unit tests: ./gradlew :app:testDebugUnitTest
- Device tests (needs a running emulator/device): ./gradlew :app:connectedDebugAndroidTest
- Office samples for the app tests (dev, needs python-docx/python-pptx): python app/tools/make_office_samples.py
- Run app: build in Android Studio (Run on device/emulator)
- Corpus check: ./gradlew :engine:corpusCheck (added in task T3)
- PDF→PPTX: ./cli convert pdf-to-pptx <in.pdf> --out <out.pptx> [--fidelity] (or ./gradlew :convert:convert --args="pdf-to-pptx ...")
- PDF→PPTX corpus check: ./gradlew :convert:pptxCorpusCheck
- PDF→DOCX: ./cli convert pdf-to-docx <in.pdf> --out <out.docx> [--mode flow|exact]
- PDF→DOCX corpus check: ./gradlew :convert:docxCorpusCheck
- DOCX→PDF: ./cli convert docx-to-pdf <in.docx> --out <out.pdf>
- DOCX→PDF corpus check: ./gradlew :convert:docxToPdfCorpusCheck
- PPTX→PDF: ./cli convert pptx-to-pdf <in.pptx> --out <out.pdf>
- PPTX→PDF corpus check: ./gradlew :convert:pptxToPdfCorpusCheck

- Last session: 2026-10-19 — T19 (convert) done. `:convert` now converts DOCX→PDF with no new dependencies (JDK `java.util.zip` + `org.w3c.dom` + `:engine` only). The package is read into a small document model (`WordModel`/`DocxReader`/`Wml`): `styles.xml` is resolved the way Word does it (docDefaults → the style's `basedOn` chain → direct formatting) and `Theme.read` fills in the fonts of real documents, which name them only through `w:asciiTheme="majorHAnsi"`/`minorHAnsi` — the `a:fontScheme` in `*/theme/theme1.xml` is applied to styles, numbering and the document before the styles are read. `WordLayout` lays the document out top-down (the writer flips y): page size/orientation and margins from `w:pgSz`/`w:pgMar`, a new page per `w:sectPr`, runs at their indents with `w:spacing` before/after, `w:line` honoured as multiple/exact/at-least, tabs at `w:defaultTabStop` (default 0.5 in), justification by sharing the slack between spaces (the layout moves the following run; the writer can emit a `TJ` too), underline/strike as thin rectangles, super/subscript by ±0.33/0.14 em, all-caps, character spacing as `Tc`, list markers from `numbering.xml` (bullets with `Symbol`/`Wingdings`/`Courier` glyph mapping, decimal/letter/roman, `w:lvlText` with `%n`, `w:startOverride`, a nine-level counter stack), tables with `w:tblGrid` columns, `w:tblInd`, `w:tblCellMar`, `w:shd` shading, border grids when the source states them (directly or through the table style chain), `w:gridSpan` merges, `w:trHeight`, nested tables, rows that move to the next page when they do not fit and a table scaled down (reported) when it is wider than the text area, and pictures inline on the baseline or anchored on the page from `wp:posOffset`/`wp:align` (behind/in front). The PDF is written by hand: text uses the **standard 14** fonts with `/WinAnsiEncoding` and explicit `/Widths` (`pdf/StandardWidths.kt`, generated by the dev-only `convert/tools/make_standard_widths.py`), JPEG bytes are embedded verbatim as `/DCTDecode`, PNGs are decoded by our own `raster/PngReader` (colour types 0/2/3/4/6, bit depths 1–16, `tRNS`, filters 0–4, CRC checked; Adam7 rejected) and re-deflated as `DeviceRGB`/`DeviceGray` + `/SMask`, content streams are deflated, `/Title` comes from `docProps/core.xml` (UTF-16BE when not ASCII) and `/Producer`/`/Creator` name the converter. Two decisions worth remembering: `Tc` is **points**, not 1/1000 em (§9.4.4 — the engine reads it that way too), while the `TJ` adjustment stays in 1/1000 em; and **every font substitution is reported** (`StandardFont.isStandard`), so real documents (Calibri, Cambria, …) show notes and `hasLosses == true` — that is expected and documented as normal in `docs/CONVERT-LIMITS.md`, not a defect. The quality tables there list what is well/partly/badly converted (dropped: headers/footers, footnotes, text boxes, VML, non-PNG/JPEG pictures, fields drawn from their cached text, bidi drawn LTR, table borders as one grey grid, single-column sections). - Last session: 2026-10-19 — T18 (convert) done. `:convert` now also converts PDF→DOCX in two modes. Flow mode (default) rebuilds an editable document: the page's text runs are grouped into lines (same baseline within 0.4 em), the lines into columns (a gutter wider than 1.5 em whose sides both carry text; a provisional split is rejected unless the shorter side covers ≥25 % of the taller side's text height, because a table's far-right column looks exactly like a second column), and the lines into paragraphs (a new paragraph starts on a gap over max(1.45×leading, 0.6×size), a first-line indent, a line that stopped well short of the text margin, a size change over 12 % or a list marker; hyphenated line breaks are rejoined). Size ratios against the dominant body size (≥1.55/1.30/1.15) turn short paragraphs into built-in `Heading 1`–`Heading 3` styles; `•`/`*`/`-`, `1.`/`1)`/`a.`/`i.` markers become real `w:numPr` lists (6 abstract numbering definitions, a running list reuses one `numId`, a non-1 start becomes a `startOverride`); rows of lines with matching cells (`cellBoundaries` gaps over max(2 em, 14 pt), left edges aligned within max(1.2 em, 14 pt), width over 45 % of the column) become `w:tbl` tables; pictures are placed in reading order (a picture covering over half the page is anchored behind the text). Each PDF page becomes its own section, so `w:sectPr` supplies the page breaks, `w:pgSz`/`w:pgMar` come from the page box and the measured text extents (clamped to 0.25–1.5 in), and a multi-column page gets `w:cols`. Running heads, footers and page numbers (top/bottom 8 % band, a page-number pattern or repeat on ≥half the pages of a ≥3-page document) are dropped and reported; paragraph spacing is normalised to the detected inter-paragraph gap (≤24 pt). Exact mode (`--mode exact`) instead writes one `w:framePr` paragraph per line at its original page coordinates (`hAnchor`/`vAnchor` page, `wrap none`) plus a single paragraph holding all of the page's anchored pictures, and rasterises the page's vector art into one full-page PNG behind the text (the display list is filtered to drop `DrawRasterImage` so pictures are not duplicated). Both modes skip invisible (render mode 3) text and report rotated runs, unrecognised fonts and skipped images. New shared layer: `media/ImageBag` and `UnitSquare.placementOf` extracted from T17, and `ooxml/PackageCheck` (content types, XML well-formedness, relationship targets) now backs both `PptxValidator` and the new `DocxValidator`, which additionally checks that `w:body` ends with `w:sectPr`, that every `r:embed` resolves, that every numbering id and abstract id is defined, and that every table row has as many cells as `w:tblGrid` declares. Also fixed while testing: a page with pictures but no text dropped them (the empty-column early return), and `wp:docPr` ids were per picture block instead of unique per document. `DocxWriter` emits hand-written OOXML with schema-ordered `w:pPr`/`w:rPr` children and a deterministic ZIP. CLI: `./cli convert pdf-to-docx <in.pdf> --out <out.docx> [--mode flow|exact] [--dpi n] [--max-pages n] [--report f]`; new `:convert:docxCorpusCheck` converts every `/testdata` PDF in both modes. 27 new `:convert` tests (70 total: paragraph merging, headings, lists, tables, columns, running heads, inline/anchored pictures, frames, determinism, writer part/order checks and validator failure modes) — `./gradlew :convert:test :convert:pptxCorpusCheck :convert:docxCorpusCheck` green, DOCX corpus 22/22 (11 PDFs × both modes) and PPTX corpus 11/11, and every generated DOCX also opened with `python-docx 1.2.0` through the dev-only `convert/tools/docx_check.py` (the 22 corpus files plus 8 synthetic fixtures: a full flow document with Heading 1/2, 4 list items and a 3-column table, a two-column page, running-head pages, a two-page document, inline and anchored pictures, and an exact-mode page with a vector background). - 2026-10-19 (T18 convert): no new dependencies — DOCX is written by the same hand-written OOXML layer as PPTX. A PDF page is not a Word page, so the two modes are explicit about what they trade: flow mode rebuilds the *document* (paragraphs, headings, lists, tables) and accepts that the line breaks and the exact spacing are gone, exact mode rebuilds the *page* (`w:framePr` per line) and accepts that the text is only approximately positioned and not really editable as prose. Table borders are drawn only when the source states them — a table style keeps its `w:tblBorders` under `w:style/w:tblPr`, not under `w:pPr`, which is where the first implementation looked (fixed while debugging the fixtures) — and the grid is deliberately one grey 0.5 pt line rather than per-edge widths and colours.
- 2026-10-19 (T20 convert): no new dependencies — the reader is DOM over `java.util.zip`, the layout is pure geometry and the PDF reuses the T19 writer (`pdf/PdfOps.kt` + `pdf/PdfDocumentWriter.kt`), which grew an ellipse (four Bézier arcs, the usual kappa form) and a line (round caps/joins) op rather than a second writer. The reader resolves inheritance *eagerly* into a concrete model (`SlideDeck`/`SlideContent`/`SlideFigure`) so the layout never looks at XML: a placeholder's box/insets/anchor/wrap/levels are merged layout-over-master attribute by attribute (`p:ph` first by `idx`, then by `type`), which is the one thing a slide does not repeat from its master and the reason a hand-built deck still centres its title. One page per slide, including hidden ones (reported), because a PDF has no hidden state and the paper deck should be complete. Text uses the T19 standard-14 pipeline (same widths, same wrapping, same justification); a shape's default text format is `p:style/fontRef` over the master's other style over the theme's `a:objectDefaults`, in that precedence. Losses are reported as notes, not swallowed: charts, tables, SmartArt, OLE, media, transitions, animations, effect styles (a theme `a:effectStyleLst` entry that carries a shadow or a shape's own `a:effectLst`), dashed outlines, gradients/patterns, crops/tiles, rotation, custom geometry, fields, `normAutofit`, per-deck font substitutions. OOXML writes control characters XML cannot hold as `_xHHHH_` (python-pptx writes a `run.text` line break that way), so `ooxml/plainText` decodes them and turns the vertical tab into a line break. Acceptance is two-layered like T19: the T17 corpus round trip (`:convert:pptxToPdfCorpusCheck`, 11/11) plus five `python-pptx` decks (`make_pptx_samples.py`, dev-only) that `PptxToPdfTest` converts and re-reads with the engine.

- 2026-10-19 (open office files, app): no new dependencies — `:app` adds the internal `:convert` module next to the existing `:engine`, and the office work reuses it end to end. Type detection is a *content* sniff, never an extension or MIME check (`office/OfficeDetect`), because providers lie about both and a renamed file is exactly the case that must not crash; legacy `.doc`/`.ppt` are recognised by the OLE compound-file signature and refused with "save it as .docx or .pptx" instead of a converter failure. They are still offered by the picker and the manifest filter on purpose, so they end on that explanation rather than looking like a file the app cannot see at all. `OfficeToPdf` wraps the converter's blocking API instead of inventing an async one: the conversion is pure CPU work with no cancellation points, so it runs on one daemon thread and a `Future.get(timeout)` (30 s) abandons a result that is too slow; every failure is a `Result` with `Unsupported`, `Corrupt` or `TooLarge` and no fourth timeout class was invented (a timeout is `Corrupt` with an explicit message). All three entrances (picker, Recent, VIEW intent) share one route and one view model so they cannot drift, and a PDF picked this way goes straight to the viewer while an office file is converted on `Dispatchers.Default`. Everything the converter reports reaches the UI: the notes are written to a `<pdf>.office.txt` sidecar next to the cached PDF in `cacheDir/converted/`, and the viewer looks for it by path — that is what turns the banner on, so it survives process restarts and needs no navigation argument; the banner's "What's missing?" shows the notes verbatim, "Save as PDF" reuses the existing SAF create flow, "Open in another app" is an `ACTION_VIEW` chooser (not `ACTION_SEND`, which is what the tools' Share does), and the banner hides in edit mode because it is about the simplified view, not about blocking work. Recent entries store the kind (`pdf`/`docx`/`pptx`) beside the URI in the same Base64 TSV records, so old two-field records decode as PDFs and the row can say what the file was; re-opening re-reads the bytes rather than trusting that label. `PackageCheck.parse` now wraps `setExpandEntityReferences`/`setFeature(disallow-doctype-decl)` in `runCatching`: Android's `DocumentBuilderFactory` throws for features it does not know, and a *valid* part must not turn into a parse error — this is the first time `:convert` runs on Android, and the device tests (3 conversions, 3 banner, 2 end-to-end flow) are what prove the reader, the layout and the hand-written PDF writer work there. The three sample files are generated by a dev-only script (`app/tools/make_office_samples.py`, python-docx/python-pptx) and committed in both test trees because unit tests read test resources and device tests read assets from the test APK.

## Release build (T14)
The release variant is minified (`isMinifyEnabled`) and resource-shrunk
(`isShrinkResources`); `app/proguard-rules.pro` keeps `SourceFile` and
`LineNumberTable`. The app/engine use no reflection, so no class keeps are
needed; Compose, Activity, Lifecycle and Navigation ship their own consumer
rules. Signing material is never committed.

1. Create a keystore once (keep the file out of the repo):
   `keytool -genkeypair -v -keystore pdfpaper-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias pdfpaper`
2. Create `/keystore.properties` at the repo root (git-ignored):
   ```
   storeFile=../pdfpaper-release.jks      # relative to :app, or an absolute path
   storePassword=…
   keyAlias=pdfpaper
   keyPassword=…
   ```
3. `./gradlew :app:assembleRelease` →
   `app/build/outputs/apk/release/app-release.apk` (plus `app/build/outputs/mapping/release/mapping.txt`
   for de-obfuscating traces).
   Without `keystore.properties` the release APK is signed with the debug key:
   installable and verifiable, but not for distribution.

Verified here: `:app:assembleRelease` succeeded and produced a 1.09 MB APK
signed by the debug fallback (R8 mapping written). Installing it and opening
the corpus is the user-side acceptance step.

## Crash reporting plan (T14)
No third-party SDK, so the dependency-free build and the absence of a network
permission are preserved.

1. Install one process-wide `Thread.setDefaultUncaughtExceptionHandler` from a
   small `Application.onCreate` (first thing, wrapping the previous handler so
   the platform still shows its dialog). Record ISO timestamp, app
   `versionCode`/`versionName`, Android release/SDK, manufacturer/model,
   available heap, thread name, the full stack trace, and — when a document was
   open — the last file name/size (never its contents).
2. Persist one file per crash under app-private `files/crash/`, newest N kept
   and total bytes capped; swallow the handler's own I/O errors so it cannot
   crash a second time.
3. On next start the Home screen shows a "N recent problem reports" banner;
   sharing is explicit through the system share sheet. Nothing is uploaded and
   no network permission is added.
4. Keep a `CrashSink` interface so a hosted backend can be plugged in later,
   opt-in per build, without changing the capture path.
